# 0003: Committed card tables and how a set's printings are chosen

Status: accepted 2026-09-28, milestone 0.

## Consulted

card-data-verifier's standing knowledge, checked live against Scryfall and the 17Lands
files on 2026-09-28; the data-source steward's planning findings on Scryfall etiquette.

## Decisions

1. **One JSON file per set under `backend/src/arena_wizard/data/cards/`,** generated by
   `arena-wizard sync-cards` and reviewed as a diff. Production never calls Scryfall.
   Serialization is deterministic, so a re-run against unchanged data writes identical
   bytes (`tests/etl/test_sync_cards.py` proves both that and the converse).
2. **A set's printings are the Arena prints of its configured Scryfall queries,** plus any
   card the set's 17Lands header names that the queries missed, found by exact name and
   added with all its Arena prints.
3. **Special Guests are selected by date.** Scryfall dates each Special Guests print with
   the release of the set it ships with, so `set:spg date=2026-04-24` is exactly SPG 149
   to 158a for SOS and `set:spg date=2026-10-02` is SPG 159 to 168 for FRA.
4. **The header is stored in the table** so CI proves, offline, that every card 17Lands has
   recorded for a set resolves (`tests/golden/test_packaged_card_tables.py`). SOS resolves
   all 346 names and HOB all 193.
5. **Resolution never depends on `arena_id`.** On 2026-09-28 every FRA card and every
   Special Guests card had none.
6. **Roles, pips, and other derived fields are computed at load,** not stored, so a rule
   change never requires regenerating the tables.

## Known limits

- FRA cannot be checked against a header until 17Lands publishes a FRA file. Until then,
  a FRA bonus sheet that Scryfall has not dated to the set would be missing; the
  review screen will surface any unrecognised export line.
