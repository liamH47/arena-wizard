# Deploying the private instance

The owner does these steps once, in this order. Secrets go into Render's dashboard or
`gh secret set NAME` (interactive, never `--body`), never into chat, commits, or logs.
The deploy costs nothing: Render free web service, Neon free Postgres, GitHub Actions
(decision 0008 has the budget arithmetic).

## 1. Neon (database)

1. Create a free project at neon.com. Choose a region near the Render region in
   `render.yaml` (Oregon there, so AWS us-west-2).
2. In the compute settings, pin autoscaling to **0.25 CU minimum and maximum**. This is
   load-bearing: at 2 CU the expected use exceeds the free 100 CU-hours a month. Leave
   scale-to-zero on.
3. Keep the default database, or create `arena_wizard`.
4. Copy the **pooled** connection string: its host name contains `-pooler`. It becomes
   `ARENA_WIZARD_DATABASE_URL`. `postgresql://…` works as given; `postgres://` does not.

## 2. Google sign-in

1. At console.cloud.google.com, create a project, for example "arena-wizard".
2. Set up the **OAuth consent screen**:
   - **User type:** External. **Publishing status:** Testing.
   - **App name:** Arena Wizard. Add a support email and a developer email.
   - **Logo:** none. The Fan Content Policy forbids Wizards logos, and uploading any logo
     triggers Google's brand review.
   - **Scopes:** `openid`, `email`, `profile` only.
   - **Test users:** add every friend's Google address.

   In Testing, anyone not on that list sees **Google's own error page** and never reaches
   the app's "ask the owner" page. Keep the test-user list and `ARENA_WIZARD_ALLOWED_EMAILS`
   in sync.
3. Create an **OAuth client ID** under Credentials, of type Web application:
   - **Authorised redirect URIs:** `https://<your-service>.onrender.com/auth/google/callback`
     and `http://localhost:5173/auth/google/callback` (local development).
   - Keep the client ID and client secret for step 3.
4. Moving the consent screen to "In production" (optional, only if the group outgrows 100
   test users) needs a homepage and a privacy policy. The policy must say what the app
   stores: Google email, name, and picture; pools; results; and pasted data.

## 3. Render (web service)

1. At dashboard.render.com, choose **New → Blueprint**, pick this repository, and apply
   `render.yaml`. This must be a workspace with **no other free web service** (750 free
   instance hours a month; one always-awake service uses 744).
2. When the Blueprint asks for the `sync: false` values, enter:

   | Variable | Value |
   |---|---|
   | `ARENA_WIZARD_GOOGLE_CLIENT_ID` | from step 2 |
   | `ARENA_WIZARD_GOOGLE_CLIENT_SECRET` | from step 2 |
   | `ARENA_WIZARD_PUBLIC_URL` | `https://<your-service>.onrender.com`, no trailing slash |
   | `ARENA_WIZARD_ALLOWED_EMAILS` | comma-separated friends' Google addresses |
   | `ARENA_WIZARD_OWNER_EMAIL` | your Google address |
   | `ARENA_WIZARD_DATABASE_URL` | Neon's pooled string from step 1 |

   `ARENA_WIZARD_SECRET_KEY` is generated by Render. `ARENA_WIZARD_ENV=prod` and
   `ARENA_WIZARD_AUTH=google` are pinned in `render.yaml`. The app refuses to boot on
   Render without them, and names anything that is missing.
3. Deploys follow CI: `autoDeployTrigger: checksPass` deploys a commit on `main` once every
   check is green.

## 4. GitHub repository variables

Under Settings → Secrets and variables → Actions → Variables:

- `APP_URL` = `https://<your-service>.onrender.com`
- `KEEP_WARM` = `true` during event windows, `false` (or unset) otherwise. With it on,
  `.github/workflows/keep-warm.yml` pings `/healthz` every five minutes, so the app never
  sleeps mid-event. The ping does not wake Neon.

Add the new "E2E (Docker image)" check to `main`'s required checks.

## 5. First-deploy checks

```
curl -s https://<your-service>.onrender.com/healthz
curl -s https://<your-service>.onrender.com/readyz
curl -s "https://<your-service>.onrender.com/readyz?deep=1"
```

- `/healthz` is `{"status":"ok"}`.
- `/readyz` shows the deployed `commit` and `last_db_error: null`.
- `?deep=1` adds `"database":"ok"`. The first call may take a few seconds while Neon wakes.

Then:

1. Sign in on a desktop and on a phone with a listed address.
2. Paste a pool and build.
3. Record a result, then open the same pool on the other device.
4. Try an address that is a Google test user but not in `ALLOWED_EMAILS`: it should see the
   denied page.

If anything fails, start with `DEBUGGING.md`.
