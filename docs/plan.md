# Arena Wizard implementation plan

Status: final, 2026-09-28. Designed against the brief in Appendix A, reviewed by a six-member panel (edge-case-hunter, test-architect, data-source steward, sealed analyst, recommendation auditor, event-night reliability), adjudicated in section 18. Every number below that came from a measurement says so.

## 1. Context

The owner and a few experienced friends play Best-of-One Sealed on Arena. The Reality Fracture (FRA) Arena Direct runs 2026-10-02 to 10-11 and pays a Collector Booster box at seven wins. Today "which 23 of these 83 cards, in which two colors" is decided by feel with 17Lands numbers looked up by hand. The public 17Lands game files (SOS: 42,403 games over 7,538 pools; HOB: 55,086 games over 9,685 pools) hold every player's full pool, the deck they built, and the result, so a deterministic builder can be calibrated against real outcomes instead of taste and its disagreements with strong players can be published.

Outcome: a public repo and a private app. Paste an Arena export, get the top decks with a scored breakdown, the observed and shrunk value of every number with its source and sample size, and template text naming the trade-off between decks; record wins and losses per deck; watch cards and color pairs move over the format. The engine is pure Python, the ETL is idempotent, the evaluation harness is the definition of done, and a specialist panel with real disagreements decides scoring, ETL, schema, user-data, and data-source changes.

Three things the panel changed that the owner should know first:
- **17Lands' JSON endpoints are off until 17Lands says yes.** Their usage guidelines discourage automated use of the API without explicit permission and ask third-party tools not to present a new set's data before its twelfth day on Arena (FRA: 2026-10-10). The public files are the primary source and are CC BY 4.0. The endpoint adapter ships behind a permission flag that defaults to off, and the owner posts the request on day one.
- **For the FRA event the engine runs on expert ratings, curated bombs, castability, curve, and rarity priors, all labelled.** No FRA sealed file exists for weeks, the draft endpoint returns almost no data unauthenticated (measured: at most 14 games per card for SOS), and the embargo covers the event anyway. That is honest and still useful; the harness measures how far below data-driven mode it lands.
- **Two scoring rules were wrong and are replaced:** the Karsten-style consistency penalty would have stripped double-pip cards from every normal two-color deck, and "first source above a game floor" would have let a thin Arena Direct sample replace a better prior. Section 7 has the replacements.

## 3. Domain model

All in `domain/`, `@dataclass(frozen=True, slots=True)`, full type hints, Google docstrings, `StrEnum` enums.

- `Color` W U B R G. `Rarity`. `Role`: creature, removal, card_advantage, fixing, evasive, combat_trick, counterspell, land.
- `Format`: `bo1_sealed`, `trad_sealed`. `EventType`: `Sealed`, `TradSealed`, `PremierDraft`, `ArenaDirect_Sealed`. Stats carry an `EventType`; configs, pools, builds, and runs carry a `Format`.
- `ColorSet(code)`: WUBRG-ordered string; 17Lands `main_colors` is already in that order (measured).
- `Card(scryfall_id, name, front_name, set_code, collector_number, arena_id: int | None, colors, color_identity, mana_cost, mana_value, pips: Mapping[Color, int], hybrid: bool, type_line, rarity, oracle_text, produced_mana, is_basic, image_uri, image_artist, roles: frozenset[Role])`. `front_name` is the join key to 17Lands, which never uses `A // B` (measured: 36 SOS, 17 HOB, 21 FRA split names).
- `ParsedLine`, `ParseWarning(kind: unknown_name | wrong_set | alternate_printing | unparsed | basic_in_pool | pool_size)`.
- `PoolEntry(card, count)`; `Pool(set_code, format, entries, basics, warnings)` with entries sorted by (front_name, collector_number), duplicates merged, `nonbasic_count`. A multiset, never a list of repeats.
- `SetConfig(code, name, arena_release_date, paper_release_date, embargo_until, formats, card_set_codes, seventeenlands_expansion, nonbasic_pool_range, stats_sources)`. `embargo_until = arena_release_date + 11 days`. All windows and `start_date` values use `arena_release_date` (measured: 44% of SOS and 51% of HOB games predate the paper date). Ranges: SOS (81, 85), HOB (78, 84), FRA (78, 86) until measured. `card_set_codes` are the day-one codes (SOS: SOS, SOA, SPG); once a 17Lands file exists the set's card list is the file header, resolved by exact front name against Scryfall across all sets (measured: SOS pools contain ten SPG Special Guests cards in up to 7% of pools).

- `CardStats(... games_gih, wins_gih, games_oh, wins_oh, games_drawn, wins_drawn, games_gns, wins_gns, decks_with, decks_total, source)` with rate properties returning `float | None`, never 0.0 for an empty denominator.

## 4. Data layer

**Sources.** `sources/base.py` defines `SourceContext(client: httpx.Client, sleep: Callable[[float], None], clock: Callable[[], datetime])`; every fetch takes a context, never a module-level client. `sources/http.py` builds the client with `User-Agent: arena-wizard/<version> (+repo url)`, `Accept: application/json`, `httpx.Timeout(connect=10, read=30, write=10, pool=10)`, per-host spacing (Scryfall search 500 ms, other Scryfall 100 ms, 17Lands 1 s), and back-off on 429.

- `seventeenlands_files.py` (primary): `head_file(ctx, set, event_type) -> FileHead(etag, last_modified, bytes)`; `stream_games(ctx, url) -> Iterator[GameRow]` streams through `gzip` and `csv.reader` with `encoding="utf-8", newline=""` (the Windows default is cp1252 and decodes the Hobbit file into garbled accented names without error, measured), strips a leading BOM, and yields sparse rows (about 86 non-zero cells of 1,730, measured); `compute_daily_aggregates(rows, header) -> DailyAggregates` is pure. Files: `https://17lands-public.s3.amazonaws.com/analysis_data/game_data/game_data_public.{SET}.{EventType}.csv.gz`, CC BY 4.0, refreshed by 17Lands occasionally (SOS last 2026-06-05, HOB 2026-09-03), with no S3 version ids.
- `seventeenlands_api.py` (permission-gated): `fetch_color_ratings` and `fetch_card_ratings` with pure `parse_*` raising `ShapeError`. The adapter refuses to run unless `config/sources.yaml` records `seventeenlands_api: {permission_granted_on, granted_by, scope}` and `docs/decisions/` holds the entry. Until then no code path calls 17Lands except the file HEAD and downloads. Null rates map to `None`; a source row counts only when its rate is non-null and `games >= min_rate_games` (measured: Arena Direct rates are null below 500 GIH games).
- `scryfall.py` (developer-run only): `arena-wizard sync-cards --set SOS` uses `/cards/search?q=set:sos game:arena&unique=prints` (500 ms spacing) plus `/cards/named?exact=` for header names outside the set's codes, writes `data/cards/{SET}.json`, and the diff is reviewed in a PR. Production never calls Scryfall; images are hotlinked `normal` URIs, never proxied.
- `config/ratings/{SET}.yaml`: expert grades with citations (LSV, Lords of Limited, Limited Resources), mapped 2.5 to 0, 3.0 to +1.5, 3.5 to +3.5, 4.0 to +6 points; the source of last resort above the rarity prior.

**ETL** (`etl/refresh.py`): `run_refresh(settings, session_factory, ctx, *, now, force=False) -> RefreshRun`. Steps are independent and each is recorded with duration, rows, and error; a failed step leaves status `partial`, and due-ness keys on the last successful step with hourly retry. Steps: (1) file loads: HEAD each `(set, event_type)` in `stats_sources`, skip when ETag and sha match, else stream, hash, aggregate, and replace aggregates and the `source_files` row in one transaction; (2) endpoint polls, only when permission is recorded, once per UTC day per set, `ArenaDirect_Sealed` every 6 hours only while that set has a live event. Due-ness is checked from an in-process timestamp first so the keep-warm ping never opens a database session (a test asserts it). Overlap: `claim_refresh(session, *, now, trigger, boot_id) -> UUID | None` marks `running` rows from another boot id or older than 30 minutes `abandoned`, then inserts under a partial unique index on `status='running'`; a run deadline of 20 minutes is checked between steps and the endpoint reports `stuck` past it. Peak memory via `psutil` (the `resource` module does not exist on Windows).

**Idempotency, per write.**

| Table | Natural key | Constraint | On conflict |
|---|---|---|---|
| users | user_id (Google sub) | pk | upsert email, name, picture, last_seen_at |

`etl/upsert.py` dispatches `{"sqlite": sqlite.insert, "postgresql": postgresql.insert}[dialect]` with no branch, and a unit test compiles both. `inputs_key = sha256(pool_hash, config file hash, bombs file hash, ratings file hash, card table hash, snapshot content hash, ENGINE_VERSION)`.

**Memory.** Streaming rows, counters in `array('q')` per day and card, under 1 MB of aggregates per set; SOS parses in about 9 seconds (measured on this machine). The ETL runs inside the web instance as a background thread launched by `POST /api/refresh`, the same function the CLI runs; if peak RSS ever exceeds 300 MB the documented fallback is running `arena-wizard refresh` on the Actions runner.

## 5. Database schema

Portable SQLAlchemy 2 types; `MetaData(naming_convention=...)`; a UTC `TypeDecorator` for timestamps (SQLite returns naive times otherwise); `PRAGMA foreign_keys=ON` in every SQLite session; explicit `ON DELETE` on every foreign key (pools cascade to builds and decks; deck_runs restrict, so deleting a pool with recorded runs is a 409, not a silent loss).

Tables: `users`; `source_files`; `card_stats_daily`; `color_pair_daily`; `endpoint_polls`; `endpoint_card_ratings`; `endpoint_color_pairs`; `pools(id, user_id, set_code, format, source, raw_text, body_hash, entries json, basics json, warnings json, pool_hash, created_at, updated_at)`; `builds(id, pool_id, inputs_key, config_version, snapshot_as_of, created_at)`; `decks(id, build_id, deck_index, colors, splash, spells json, lands json, total, total_se, breakdown json, explanations json)`; `deck_runs(id, user_id, deck_id, wins, losses, event_name, notes, extra json, body_hash, created_at, updated_at)`; `refresh_runs(id, boot_id, trigger, status, started_at, finished_at, steps json, peak_rss_bytes, error)`. There is no `cards` table: the resolver and every join read the committed card tables from package data at import.

Snapshots are sums over `card_stats_daily` for cumulative or rolling windows, computed in SQL and cached in-process for ten minutes; per-source means by rarity are computed with them. Size: well under 100k rows per mature set; Neon's free half gigabyte holds years.

Alembic: `env.py` takes the URL from `Settings().database_url`; offline `literal_binds`; files `versions/NNNN_snake.py` with hand-set revisions and a reasoned docstring; `downgrade()` counts rows and refuses to destroy data unless `ARENA_WIZARD_ALLOW_DESTRUCTIVE_DOWNGRADE=1`; `op.batch_alter_table` for column changes; `docs/schema.md` changes in the same commit; `alembic check` runs in CI.

## 6. Engine: parsing and resolution

**Export grammar** (`export_parser.py`): `^(\d+)\s+(.+?)\s+\(([A-Z0-9]{2,5})\)\s+([A-Za-z0-9★†-]+)\s*$`; section headers, blank lines, `About` and `Name` lines skipped; CRLF, tabs, non-breaking spaces, and a leading U+FEFF tolerated (measured: only the BOM broke the draft grammar); counts accumulate across repeated lines; unparsed lines become warnings; the function is total.

**Resolution** (`resolver.py`), maps loaded from package data: (1) exact `(set_code, collector_number)` within the set's card table, which includes bonus-sheet and Special Guests printings; (2) else front-name match within the set's card list, warning `alternate_printing`; (3) else front-name match across all card tables, warning `wrong_set`, included with stats `None`; (4) else `unknown_name` with up to three `difflib` suggestions as one-tap fixes. Basics go to `Pool.basics`. Pool size is advisory: "83 non-basic cards; SOS pools run 81 to 85 (mode 83)". The review screen shows "N lines not recognised; they will be in no deck" directly above Build. A CI test asserts every name in each pinned 17Lands header resolves.

**Roles** (`roles.py`): regex classification over type line and oracle text, golden-tested on 60 hand-labelled cards per set and checked by the card-data verifier.

## 7. Engine: value, objective, builder

**Card value** (`shrink.py`, `scoring.py`). Sources in order of information, not priority: Sealed file, Arena Direct endpoint (when permitted), draft proxy (from the PremierDraft public file through `ProxyFit`), expert rating, rarity mean. Each source has its own games-weighted mean by rarity (measured: Arena Direct players win more, and mythics accrue about a tenth of a common's games, so a format-wide mean taxes bombs). The Bayesian chain: the best lower-information source is the prior, not a fallback: `gih_s = (wins + K_p * prior) / (games + K_p)` with `K_p = m(1-m) / residual_var` of that prior, so a 300-game Arena Direct sample tightens a proxy instead of replacing it. `K` for the format mean is estimated by method of moments on SOS and HOB at milestone 1, separately for IWD. `q = 100 * (gih_s - m_rarity_source) + w_iwd * 100 * iwd_s`. A card with no data anywhere gets `q = expert grade` if rated, else `100 * (m_rarity - m)`. Every term records `observed`, `used`, `prior_share = K / (n + K)`, `source`, `sample`.

**Deck objective.** `S = w_card * sum(q) + w_pair * 100 * (pair_wr_s - pair_mean) + w_bomb * sum(1.5^-k over ranked bombs) - w_creature * dist(creatures, 13..17) + w_removal * min(removal, 5) + w_two * min(two_drops, 4) + w_three * min(three_drops, 4) - w_top * max(0, five_plus - 4) - w_consistency * sum(shortfall) - w_splash_card * n_splash`. `shortfall(c) = 10 * max(0, P_cast(c, 8 sources) - P_cast(c, actual sources))`, hypergeometric at turn mana value plus one on the play, computed from mana symbols (hybrid cards join every pair they can be cast in). Pair term omitted with source none when no pair data exists. Weights `version: "0.2"`: card_quality 1.0, iwd 0.35, pair_strength 0.5, bomb 1.5, creature_balance 0.8, removal 0.6, two_drop 0.4, three_drop 0.4, top_end 0.5, consistency 0.7, splash_card 0.8. Every term is additive per card or a capped count tracked incrementally, so a swap is an O(1) delta; a property test asserts `delta == S(after) - S(before)`.

**Builder** (`builder.py`): for each of the ten pairs with at least 23 castable non-land playables, greedy fill by q with role minimums, then a hill climb over a neighborhood of the bottom 8 included and top 8 excluded by value plus the top 4 excluded and bottom 2 included per role, at most 25 steps, strict gains only, name tie-breaks; both 24/16 and 23/17 evaluated. Splash candidates: at most 3 cards with exactly one splash pip and mana value 4 or more or role removal, evaluated for any pair whose admissible bound (sum of its 3 best splash candidates' q minus its 3 weakest included minus 3 times `w_splash_card`) reaches the current third-best total, with at least 3 sources. Output: top 3 plus any deck within one `total_se` of the third, with `gap_to_next` and a "toss-up" label when the gap is under one SE; `total_se` propagates per-card SE from `games`. Fewer than three candidates is handled, never an index error. Budget: an evaluation-count budget per pool asserted in a unit test, and a wall-clock check on CI only.

**Lands** (`lands.py`): 17 unless average mana value is under 2.7 and at most two cards cost 5 or more; basics split by pips weighted 1.5x under mana value 4, at least 6 per main color; splash gets 1 basic plus fixing, 2 if sources would be under 3.

**Explanations** (`explain.py`): templates over breakdown deltas versus the next deck, always naming stream, window, and n: "Color pair BG: 58.1% observed, 56.4% used (n=310, 39% prior), Sealed game file through 2026-06-05". Proxy and expert values are labelled as such with the fit's residual SD in points and the draft side's n and as-of.

**Bombs** (`engine/bombs.py`): `b = z(gih_s) + 1.0 * z(iwd_s)` with rarity-relative shrinkage, floor 150 games, computed only when at least 50 cards qualify; the F1 against the curated list picks the threshold on SOS and it is applied unchanged to HOB. Curated YAML entries have `action: add | remove | annotate`, `note`, `source`, and `add` means the expert holds it a bomb regardless of the auto list.

**Trends** (`trends.py`): cumulative and rolling-7 windows from `arena_release_date`; movers ranked by `z = delta / SE` with the SE shown, `|z| < 2` listed under "no significant movement"; a negative endpoint delta is None with reason "restated", never clamped to 0. Before `embargo_until`, a set's trends and bombs pages return "embargoed by 17Lands until {date}" with a link, and endpoint-sourced FRA terms show only the transformed `q` and label.

## 8. Evaluation harness

**Eval set.** `arena-wizard eval build-set --set SOS --set HOB` verifies each Sealed file against `eval/pins.json` (url, sha256, bytes, last_modified, games, pools, split_day, bombs yaml sha, ratings yaml sha, config version) and refuses on mismatch; groups rows by `draft_id`; takes the pool from any row (measured: identical across all rows in all 17,223 pools, and 15 to 17% of pools have no build_index 0 row); drops basics; writes one record per pool with `first_deck`, all games by build_index and day, `user_wr_bucket`, `rank`. `split_day` is the day by which 60% of games were played; the sample is 600 pools per set whose first game is after it, stratified by first-deck colors, ordered by `sha256(draft_id)`, committed. Because 17Lands re-uploads files without version ids, the pre-split aggregates are committed as `eval/aggregates/{SET}.presplit.json` and CI never downloads from 17Lands. The eval snapshot is built from pre-split file rows only: no endpoint data, the proxy fit bounded to pre-split rows, and the automatic bomb list; curated-on is reported separately. The report states that the sample is the last 40% of games by date and that user overlap across halves cannot be measured because the file has no user id.

**Metrics** (`eval/metrics.py`, pure, each with a Wilson interval or bootstrap CI): `pair_agreement_at_1` and `_at_3` (k fixed at 3, mean decks returned reported), weighted by bucket midpoint with blanks excluded and their share reported; naive baselines "best pair in format", "most playables", and "sum of raw top-23 GIH", each of which the objective must beat; `agreement_lift` and `skill_residual_lift` (reported, never gated); `within_pool_switch` (pools whose main colors changed across build_index with the engine's pair one of the two: games-weighted win rate under the engine's pair minus the other, same pool and player, full set, weekly); `deck_score_lift` (logistic `won ~ S(deck_played) + bucket` on pre-split games, out-of-sample slope and AUC); `rebuild_lift`; `deck_overlap_at_pair` (Jaccard over 23 spells versus the player's deck constrained to their pair); `bomb_f1` with the named diff of missed and extra cards; `legality` (40 to 44 cards, counts within pool, 16 or 17 lands, castable); `three_color_share` (measured: 5.3% of SOS and 10.1% of HOB players ran more than two colors; a pairs-only builder cannot match them, reported as a known limit); `crosscheck_pairs` and `crosscheck_cards` weekly only, endpoint bounded to the file's last game day, empty comparison is a failure; `proxy_fit` on the PremierDraft public files restricted to Arena days 1 to 7 as predictor with covariates removal, mana value 5 or more, and rarity, fit on one set and tested on the other; proxy is disabled when the fit is unavailable or cross-set R² is under 0.3, labelled weak under 0.5, and otherwise weighted through `K_p`.

**Gate** (`eval/gate.py`, pure `gate(report, base, thresholds) -> tuple[GateFailure, ...]`): CI compares `eval/report.json` against `git show origin/main:backend/eval/report.json`, never against a file the PR can rewrite; a missing metric fails; comparisons in integer basis points; failures when legality is under 1.0, an agreement metric drops more than 300 basis points, a naive-baseline margin is under 500, the bomb diff loses a curated card, or a cross-check exceeds its bound. An accepted regression needs an `eval/accepted.json` entry citing a decision record. Deltas are shown as flip counts (k worse, j better). `report.json` carries a decision digest, provenance (config version, sample sha, bombs and ratings sha, card table sha), and metrics rounded to 4 places; `report.md` is rendered by a pure `render_markdown(report_json)` and checked byte for byte. Bootstraps are seeded. Determinism is tested in two subprocesses with different `PYTHONHASHSEED` values.

**Disagreement ledger** (`eval/ledger.py`, in `report.md`): for every sample pool where the engine's top pair differs from a top-two-bucket player's first deck: the five highest-q cards, engine pair and total, the engine's total for the player's pair, the player's record, and whether a later build switched to the engine's pair, sorted by gap. The switch column gives a calibration curve for free.

## 1. Goal

The owner and a small group of experienced friends want to understand each set's sealed metagame and win physical product in Arena Direct events, where seven wins earns a Collector Booster box. They can spot miscalibrations themselves, so the engine must show its reasoning: scores with breakdowns, sample sizes, and the source of every number.

## 2. Users and access

- A private friend group. Google sign-in gated by an allow-list held in an environment variable. Listed users see "Sign in with Google" and get in; unlisted users see a friendly page saying to ask the owner. A database-backed admin page is a later upgrade only if needed.
- Each user has an account and a result history: a wins and losses record per deck run. Keep the schema open to more fields later (opponent colors, deck edits between runs).

## 3. Scope

- **Format.** Best-of-One Sealed only in v1. Format is a first-class field on every data record, scoring config, and UI filter so Traditional sealed can be added later without a rewrite.
- **Sets.** Reality Fracture (code FRA) is the target; it reaches Arena on 2026-09-29 and has no 17Lands data yet. Calibrate and validate on The Hobbit (HOB, released 2026-08-14) and Secrets of Strixhaven (SOS, released 2026-04-24), which have mature sealed data. Multi-set from day one behind a set abstraction: adding a set is configuration plus a data refresh, not code.
- **Pool input.** Pasted Arena export text is the primary path. Desktop export is confirmed; whether the Arena mobile and tablet clients can export a Limited-event deck is unverified and the owner will check. A screenshot importer behind the same importer interface is in v1 scope so phones and tablets are covered either way, and it feeds the same review screen. Pools are addressable by URL so a pool pasted on a desktop can be opened on a phone.
- **Devices.** Desktop and phone use are both first-class during events. A responsive layout is a v1 requirement, not a polish item.
- **LLM use.** None in v1. Parsing, deck building, scoring, and explanations are deterministic Python; explanations are templates over the scoring breakdown. The screenshot importer should use classical matching (perceptual hashing against Scryfall images, or OCR of the name line). A single vision API call is acceptable only if classical matching proves unreliable on real Arena screenshots, and then the per-screenshot cost must be stated.
- **Trends.** Daily snapshots over the whole format, release to next release, with a movers view for cards and color pairs.
- **Bombs.** A data-driven score plus a curated per-set list. Calibrate the threshold on SOS and HOB so the automatic list matches experienced-player intuition; the curated list adds, removes, or annotates.
- **Refresh.** A nightly scheduled refresh and a manual refresh button, both calling the same idempotent code path.
- **Sources.** 17Lands is primary. The source layer is an adapter interface so other sources can be added for calibration or early-format coverage.

## 4. Data sources: verified facts

### 4a. 17Lands public datasets: the source for sealed card statistics

- URL pattern: `https://17lands-public.s3.amazonaws.com/analysis_data/game_data/game_data_public.{SET}.{EventType}.csv.gz`. Verified by HEAD on 2026-09-28: SOS Sealed 4.0 MB (last modified 2026-06-05), HOB Sealed 4.2 MB (2026-09-03), SOS TradSealed 1.7 MB, SOS PremierDraft 49 MB, FIN Sealed 6.1 MB. No ArenaDirect_Sealed file exists (403). Files appear three to six weeks after release and are refreshed occasionally, not daily. ETL keys on Last-Modified or ETag plus a content hash.
- License CC BY 4.0. Index page `https://www.17lands.com/public_datasets` is JavaScript-rendered.
- SOS Sealed file contents, verified: 42,403 games. Metadata columns: expansion, event_type, draft_id, draft_time, game_time, build_index, match_number, game_number, rank, opp_rank, main_colors, splash_colors, on_play, num_mulligans, opp_num_mulligans, opp_colors, num_turns, won, user_n_games_bucket, user_game_win_rate_bucket. Then five families with one column per card (346 for SOS including five basics and Special Guests; 193 for HOB): `deck_`, `sideboard_`, `opening_hand_`, `drawn_`, `tutored_`. Card names containing commas are quoted; use a real CSV parser.
- What this gives you. Every 17Lands card statistic (game-in-hand win rate, opening-hand win rate, improvement when drawn, play rate) is computable from the file per day via `game_time`, which is how daily trend snapshots are produced. `deck_` plus `sideboard_` reconstructs each player's full pool; `main_colors` and `won` give the deck they built and the result; `draft_id` groups the games of one pool; `user_game_win_rate_bucket` allows weighting by player skill. That is thousands of real pools with real decks and outcomes for calibration. A 62k-game file expands to about 50 MB of CSV, so stream or chunk and store aggregates, not raw rows.
- Measured 2026-09-28: basic lands never appear in `sideboard_` columns; decks carry 12 to 17 basics from Arena's unlimited supply; non-basic pool size is a range (SOS mostly 81 to 85, mode 83; HOB mostly 78 to 84, mode 81); decks are 40 cards in the vast majority; games per pool 1 to 9.

### 4b. 17Lands website JSON endpoints: live signals only, permission required

Undocumented, unauthenticated, used by community tools. The usage guidelines discourage automated use without explicit permission and prefer the public datasets; they also ask third-party tools not to present a new set's data until its twelfth day on Arena. Verified on 2026-09-28:

- Color pairs: `https://www.17lands.com/color_ratings/data?expansion=HOB&event_type=Sealed&start_date=2026-08-01&end_date=2026-09-28&combine_splash=true` returns color-pair records (`is_summary`, `color_name`, `short_name`, `wins`, `games`). Works for Sealed: HOB about 62k games, SOS about 44k.
- Arena Direct cards: `https://www.17lands.com/card_ratings/data?expansion=SOS&format=ArenaDirect_Sealed&start_date=2026-04-14&end_date=2026-09-28` returns card records (name, mtga_id, color, rarity, url, types, game_count, pool_count, play_rate, opening_hand_win_rate, drawn_win_rate, ever_drawn_win_rate which is GIH WR, never_drawn_win_rate, drawn_improvement_win_rate, plus draft-only seen and pick fields). SOS has real data: 29 cards above 1,000 games, maximum 2,686; rates are null below 500 games. HOB's is essentially empty.
- The same card endpoint with `format=Sealed` returns game_count 0 for every card on SOS, HOB, and FIN; `TradSealed` returns tiny counts; `PremierDraft` returns at most 14 games per card unauthenticated for SOS. The website does not serve card-level statistics for regular sealed or, without an account, for draft; the public files do.
- A set not yet tracked returns an empty JSON array, not an error (verified with FRA). Treat an empty list as "no data yet".

### 4c. Scryfall

`https://scryfall.com/docs/api`: free, no auth, bulk downloads; cards carry `arena_id`, set code, collector number, colors, mana value, types, rarity, oracle text. Needed to resolve Arena export lines (`1 Card Name (SET) 123`) into card objects, to classify removal and other roles from oracle text, and for images. Search endpoint 2 requests per second, others 10; both User-Agent and Accept headers required. Arena-legal counts on 2026-09-28: SOS 271, SOA 65, HOB 193, FRA 284 with no `arena_id` yet. The Wizards Fan Content Policy applies (free, no ads, disclaimer, no Wizards logos); mtg-calc's `docs/roadmap.md` records the terms. The README and the app carry the required disclaimer and the 17Lands credit, because both the repo and the app are public.

### 4d. Early-format strategy and other sources

- Before a sealed file exists for a set: expert ratings from set reviews with citations, curated bombs, castability and curve, and rarity means from prior sets, all labelled; the draft proxy from the PremierDraft public file once it exists; endpoint data only with recorded permission and after the embargo. Label every number with its source and sample size.
- Reference and prior sources, not dependencies: sealeddeck.tech, Draftsim ratings, set reviews from Limited Resources, LSV, and Lords of Limited, MTGJSON. Untapped.gg has no public API.
- Optional extra pool inputs to evaluate: the 17Lands tracker records sealed pools and sealeddeck.tech opens them by id; Arena's local `Player.log` contains the pool.

### 4e. Attribution and etiquette

17Lands requires a visible top-level credit with a link and no implied endorsement. Mirror data on a schedule; never call 17Lands per user request; endpoint use only with recorded permission. Send an identifying User-Agent.

- FRA Arena Direct 2026-10-02 through 2026-10-11: Best-of-One Sealed, play to 7 wins or 2 losses; three to six wins earn gems and packs, seven wins a Collector Booster box while supplies last. Source: MTG Arena announcements, 2026-09-28.

- SOS Arena Direct has run and is the only Arena Direct sample with real size.

## 6. User workflow

1. Sign in with Google; the allow-list decides.
2. Pick set and format; format defaults to Bo1 Sealed.
3. Paste the Arena export. Guidance beside the box: in Arena, add every card in the pool to the deck, press Export, paste here. Export lines carry counts; the pool is a multiset and duplicates are normal.
4. Review screen: parsed pool with names or images, counts, colors, rarity, all editable. Validation is advisory, never blocking: a per-set expected pool size from configuration, a tolerance for basic lands that came from packs, warnings for unknown names or wrong-set cards. The owner is the authority on their own pool.
5. Confirm. The engine enumerates color pairs and supportable splashes, builds candidate 40-card decks, scores them, and returns the top two or three, more if close, each with a breakdown and template trade-off text such as "two bombs but two fewer removal spells than the next option".
6. Output is a copy-friendly list sorted the way Arena sorts, because Arena cannot import a deck during a Limited event.
7. The user records wins and losses against the deck they played.
8. Trends page (cards and color pairs over the format, daily, with movers) and bombs page (data-driven plus curated, per set).

## 7. Engine requirements

- Pure and deterministic: no I/O inside the engine; data is passed in. Docstring and full type hints on every function. Frozen, slotted dataclasses for domain objects. No dataclasses for throwaway locals.
- Scoring inputs: card quality (GIH WR and improvement when drawn, shrunk toward a prior by sample size), color-pair strength, deck balance, and bomb weight. Weights live in per-set, per-format config, never in globals.
- Calibration and evaluation run through the harness in Working method. Treat agreement as a calibration signal with selection bias, not ground truth. Weights are tuned against the harness, never by hand-waving.
- Trends: daily cumulative and rolling windows from `game_time`; movers with sample-size floors. Missing data is None, never zero.
- Bombs: a score thresholded to match experienced-player intuition on SOS and HOB, plus a curated per-set file.

## 9. Engineering standards

- Python 3.13, uv (`pyproject.toml`, `uv.lock`, a dev dependency group, `uv sync --frozen` in CI and Docker), FastAPI, SQLAlchemy plus Alembic, Postgres in production and SQLite in tests, pydantic-settings config that refuses to boot half-configured and names what is missing, pydantic models only at the API boundary.
- ruff check and `ruff format --check`, line length 100, rules E, F, I, UP, B, SIM, and D with the Google docstring convention outside tests. `mypy --strict`. Modern type syntax.
- pytest with branch coverage gated at 100, ratcheted only upward. `main()` and `__main__` excluded and never unit-tested; logic is extracted into pure functions. Test names describe scenario and expected outcome. Tests never assert on mocks. Idempotency tests must fail for a non-idempotent implementation.
- Pure core, I/O at the edges: `fetch_x` does I/O only, `compute_x` is pure, `main()` orchestrates. Test seams are optional injected parameters such as an `httpx.BaseTransport`.
- Every write answers "what happens if this runs twice?" Migrations ship with a real `downgrade()` and change together with models and the schema doc.
- `encoding="utf-8"` on every file read. `.gitattributes` forces LF. No `make` on the host. Containers run on UTC.
- Frontend: React 19, TypeScript, Vite, Tailwind v4, oxlint, Playwright end-to-end; TypeScript strictness plus end-to-end tests rather than blanket component tests. Built in a Node stage and served same-origin by FastAPI from a multi-stage, non-root Docker image with `/healthz` and `/readyz`.
- CI on push to main and pull requests: backend job (`uv sync --frozen`, ruff, format check, mypy, pytest), frontend job (`npm ci`, lint, typecheck, build), Docker build. A local `verify` skill mirrors CI exactly.
- Git: the repo is public from the start and doubles as portfolio work, so keep app logic lean and put visible effort into CI, tests, and observability. Rename `master` to `main` before adding any workflow. Kebab-case feature branches, commits at checkpoints, imperative subjects with evidence in the body, a PR with Summary and Test plan sections at the end. `Co-Authored-By: Claude` trailers stay; session URLs, email addresses, and the allow-list never go into the repo.
- Secrets never in chat, commits, or logs; `.env.example` documents every variable; `gh secret set NAME` interactively, never `--body`.
- Decisions and runbooks live in the repo: a roadmap with "decisions already made", a DEBUGGING.md, a "known broken, do not paper over" list. Ask a decision once; never re-ask.
- Data ethics: free sources only; robots.txt and terms of service are hard stops; visible credit; terms settled before an adapter ships.
- Specialist agents are read-only, run in parallel, have mandates narrow enough to disagree, and are adjudicated in writing, per Working method.
